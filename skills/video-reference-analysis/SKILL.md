# 参考视频分析

使用 `video-analyzer` MCP 读取视频事实，再从电商创作角度提炼可迁移的结构。分析阶段只读，不选择本地/API 路线，不查询余额，不连接 ComfyUI，也不调用任何视频生成接口。

## 分析流程

1. 对一个本机视频或单条视频链接调用 `analyze_video`。默认使用 `standard` 细节级别，以时间线、字幕、OCR、元数据和关键帧为依据。
2. 先检查工具返回的 `warnings`。缺少字幕、音轨或部分帧时仍可分析可见内容，但必须在结论中说明哪些信息没有验证；不要猜测听不清的台词、商品功能或销售数据。
3. 只有关键动作、转场或文字变化无法从关键帧判断时，才对对应时间段调用 `analyze_moment` 或 `get_frame_burst`。不要为了“更完整”无目的地抓取整段密集帧。
4. 输出一份简洁、可检查的报告：
   - 视频概况：时长、画幅、内容类型、目标受众与核心表达；受众和目的属于推断时要标明。
   - 时间线：每段的画面、主体动作、镜头、转场、字幕/口播、声音及该段作用。
   - 有效机制：开头钩子、卖点出现顺序、节奏变化、信任或转化设计。
   - 可复用公式：用与原商品、品牌、人物和原文案解耦的结构描述。
   - 改编建议：说明替换成用户商品时需要哪些素材，以及哪些部分应保留、可调整或不应照搬。
5. 到此停止。若用户想据此生成新视频，再交给 `video-director` 根据用户自己的商品和目标重写导演方案；后续生成必须继续遵守 `ecom-h3-video` 的路线选择和最终剧本确认。

## 保存参考模板

- 即使用户一开始说“分析并保存”，也先展示分析报告和拟保存的模板摘要，并询问是否确认保存。用户修改分析后，旧确认失效。
- 用户看过当前版本并明确确认后，读取 [templates/_template.json](templates/_template.json)，在同目录新建一个 JSON。文件名使用简短英文小写连字符；不要覆盖 `_template.json` 或现有模板。
- 保存抽象后的创意结构、时间线和改编槽位，不把销量、效果或未验证卖点写成事实。模板可保留来源标签以便追溯，但不复制原品牌、人物、对白、音乐或逐字文案作为默认输出。
- 这里的模板是“参考视频模板”，不是 `ecom-h3-video/templates/` 中已经成片验证的生成模板。未经实际生成并由用户确认可用，不得移动或复制到已验证模板目录。

若当前只能访问已安装的插件缓存而没有插件源码，不写缓存；把完整 JSON 展示给用户并说明需要在源码版插件中保存。
